Gradle released [`9.9.1`](https://docs.gradle.org/9.9.1/release-notes.html) that includes a fix for
[GHSA-3cfg-jpcr-gfp3](https://github.com/gradle/gradle/security/advisories/GHSA-3cfg-jpcr-gfp3) vulnerability that
allowed arbitrary code execution from an included static version catalog TOML file. You should pick up this fix ASAP!

I helped find this vulnerability, so I wanted to share how it works.

[Gradle version catalogs](https://docs.gradle.org/current/userguide/version_catalogs.html) are TOML files that allow
you to centralize your dependencies and their versions into a single place.

If you have

```toml
[versions]
androidxCore = "1.0.0"
[libraries]
androidxCore = { group = "androidx.core", name = "core", version.ref = "androidxCore" }
```

then in `build.gradle.kts` you can add

```kotlin
dependencies {
  implementation(libs.androidxCore)
}
```

These catalogs can also be pulled from a remote repository via `settings.gradle.kts`:

```kotlin
dependencyResolutionManagement {
    versionCatalogs {
        create("mycatalog") {
            from("com.mycompany:catalog:1.0")
        }
    }
}
```

In order for your build files to be able to reference these entries a set of accessors needs to be generated by Gradle
and that's where our vulnerability pops up. TOML file is read by Gradle before the configuration phase and a Java class
is generated to `.gradle/caches/9.9.0/dependencies-accessors/XXX/sources/org/gradle/accessors/dm/LibrariesForMycatalog.java`.

```java
   public static class VersionAccessors extends VersionFactory  {
        public VersionAccessors(ProviderFactory providers, DefaultVersionCatalog config) { super(providers, config); }
        /**
         * Version alias <b>androidxCore</b> with value <b>1.0.0</b>
         * <p>
         * If the version is a rich version and cannot be represented as a
         * single version string, an empty string is returned.
         * <p>
         * This version was declared in catalog com.mycompany:catalog:1.0
         */
        public Provider<String> getAndroidxCore() { return getVersion("androidxCore"); }
    }
```

These accessors get compiled and executed during the configuration phase.

If you squint at this, you might notice that the actual version is added to Javadoc for the accessor. Sadly, Gradle
prior to the fix did not sanitize version values allowing you to have:

```toml
[versions]
androidxCore = "1.0.0 */ { System.out.println(\"Hello from Mr Bobby Version Catalog!\"); } /*"
```

and this would generate:

```java
   public static class VersionAccessors extends VersionFactory  {
        public VersionAccessors(ProviderFactory providers, DefaultVersionCatalog config) { super(providers, config); }
        /**
         * Version alias <b>androidxCore</b> with value <b>1.0.0 */ { System.out.println("Hello from Mr Bobby Version Catalog!"); } /*</b>
         * <p>
         * If the version is a rich version and cannot be represented as a
         * single version string, an empty string is returned.
         * <p>
         * This version was declared in catalog com.mycompany:catalog:1.0
         */
        public Provider<String> getAndroidxCore() { return getVersion("androidxCore"); }
    }
```

and thus anyone running **any** Gradle task in their project imports this version catalog will print out `Hello from Mr Bobby Version Catalog!`.
Yikes!

I hope this was interesting. Now go ahead and upgrade!
